## 3. Tres correcciones al maestro que este plan aplica (verificadas contra fuentes primarias, R11)

1. **"`run_tests` pasa" es un criterio vacío tal como está escrito.** gdUnit4 devuelve código 0 cuando no descubre ningún test (`"No test cases found, abort test run!"` → `RETURN_SUCCESS`). El script debe exigir un conteo mínimo de tests descubiertos.
2. **El comando de §21 está incompleto.** Sin `--ignoreHeadlessMode` gdUnit4 aborta en headless con código 103. Sin `--import` previo no descubre suites (usa la caché global de clases). La ruta `-a` debe ir como `res://…`. Comando corregido en el paso 6.
3. **Jolt NO es el default del motor en 4.7.2.** El valor `DEFAULT` de `physics/3d/physics_engine` sigue resolviendo a GodotPhysics3D; Jolt es default solo para proyectos creados desde el diálogo del editor. Un `project.godot` escrito a mano **debe** declarar `3d/physics_engine="Jolt Physics"`.

Y una contradicción maestro↔motor ya decidida por el dueño el 2026-09-08: el maestro dice "Forward+ (Vulkan)"; Godot ≥4.6 escribe `d3d12` como driver de render para proyectos nuevos en Windows. **Decisión: `d3d12`** (ver D31). La regla "shaders se verifican en ambas máquinas" no cambia.

## 5. Pasos de ejecución (Windows)

### Paso 0 — Git global de la máquina (idempotente; reportar antes de ejecutar)
```
git config --global core.autocrlf input
git config --global init.defaultBranch main
git lfs install
```
Godot escribe LF siempre; `autocrlf=true` corrompe strings multilínea en `.tscn`.

### Paso 1 — Repo y metadatos (commit inicial en `main`)
`git init` en la carpeta. Crear:

- **`.gitignore`**: `.godot/`, `/android/`, `.nomedia`, `*.translation`, `*.tmp`, `export_credentials.cfg`, `export.cfg`, `/reports/` (salida de gdUnit4), `tools/godot_bin.local`, basura de SO (`.DS_Store`, `._*`, `Thumbs.db`, `[Dd]esktop.ini`). **No** ignorar `export_presets.cfg`, `*.import` ni `*.uid`: se versionan.
- **`.gitattributes`**: primera línea `* text=auto eol=lf`; pins `text eol=lf` para `*.gd *.tscn *.tres *.godot *.import *.cfg *.uid *.gdshader *.md`; LFS (`filter=lfs diff=lfs merge=lfs -text`) para `glb gltf blend fbx obj png jpg jpeg webp tga exr hdr dds wav ogg mp3 ttf otf ico scn res lmbake`. Sin `*.svg` (D36). El orden importa: las líneas posteriores sobreescriben atributos anteriores.
- **`.editorconfig`**: `root=true`; `[*]` utf-8, lf, final newline, trim trailing whitespace; `[*.gd]` `indent_style=tab`, `indent_size=4`. (Godot ≥4.4 genera uno mínimo al crear proyectos desde el diálogo; aquí escribimos a mano, el nuestro manda.)
- **`docs/.gdignore`** (vacío) · **`docs/RUTA_FRAGIL_documento_maestro_v0.2_godot.md`** · **`docs/CONTEXTO_RUTA_FRAGIL_v0.2.md`** (ambos desde el chat, con la cabecera de D35) · **`docs/referencias/.gitkeep`** (destino del style board D16 cuando el dueño lo deposite) · este plan queda en `docs/planes/`.
- **`README.md`**: versión exacta del motor con hash `ed1daf0bf`; receta de instalación por SO (sección 6 de este plan); comandos (`tools/run_tests.*`); mapa de carpetas §20; regla "solo parches 4.7.x, nunca dev/beta" (ADR-000); `physics_ticks_per_second` fijo en 60 (default del motor, por eso no aparece en `project.godot`).
- **`AGENTS.md`**: R1–R14 textuales (§0.3), protocolo §0.4, frontera de autonomía §0.8, comandos verificados de este plan, rutas. **`CLAUDE.md`**: una línea, "Lee `AGENTS.md`".

### Paso 5 — Test trivial con contenido
`tests/smoke_test.gd`, `extends GdUnitTestSuite`, **todas** las funciones con `-> void` y todas las variables tipadas (el ejemplo mínimo de la doc de gdUnit4 omite `-> void` y dispararía D34):
- `test_engine_is_pinned_to_4_7_2` — `Engine.get_version_info()["string"]` empieza con `"4.7.2.stable"`. Protege D17/ADR-000 en ambas máquinas.

### Paso 6 — `tools/run_tests.ps1` y `tools/run_tests.sh` (misma lógica, ≤400 líneas, inglés)
1. Resolver `GODOT_BIN` (D39). Ejecutar `--version`; abortar si no empieza con `4.7.2.stable`.
2. `"$GODOT_BIN" --headless --path <raíz del repo> --import` **dos veces** (issues abiertos de Godot #97952/#102728: a veces la primera pasada no completa). Verificar que existe `.godot/global_script_class_cache.cfg`. **No confiar solo en el código de salida:** en 4.7 el apagado con plugins puede devolver ≠0 aunque el import esté completo (el fix de motor #120976 es de 4.8). Si ocurre, se registra el código y el texto exacto como hallazgo; no se esconde ni se convierte en éxito silencioso.
3. Tests:
```
"$GODOT_BIN" --headless --path <raíz> -s -d --remote-debug tcp://127.0.0.1:0 res://addons/gdUnit4/bin/GdUnitCmdTool.gd --ignoreHeadlessMode -c -a res://tests -rd res://reports
```
   Misma forma que el `runtest.cmd` oficial. `--remote-debug` en puerto 0 evita el bucle interactivo `debug>` ante errores de parseo. `-c` continúa tras fallos. **Nunca** poner `--` o `++` antes de las opciones de gdUnit4.
4. Mapear el código de salida: `0` ok · `100` fallos · `101` warnings · `103` headless rechazado · `104` versión de Godot no soportada · `105` errores de script en el descubrimiento · cualquier otro (444, 134, 0xC0000005…) = fallo de infraestructura. Imprimir el significado.
5. Leer `reports/report_N/results.xml` (JUnit; verificar el nombre exacto del atributo al ejecutar) y **fallar si tests descubiertos < 3**.
6. Salir con 0 solo si todo lo anterior pasó.

### Paso 7 — Normalizar `project.godot`
Una sola ejecución **con ventana** (el editor reescribe el archivo al arrancar solo cuando puede dibujar; headless nunca lo toca):
```
"$GODOT_BIN" --editor --path <raíz> --quit
```
Revisar el diff, aceptarlo, y verificar que un segundo arranque no produce cambios.

### Paso 8 — Sidecars, permisos y commit
El `--import` crea `*.uid` para cada `.gd` e `icon.svg.import`. **Se versionan** (si no, la Mac genera UIDs distintos y rompe referencias). `git update-index --chmod=+x tools/run_tests.sh addons/gdUnit4/runtest.sh`. Commit en `m0/t0.1-foundations` referenciando la tarea. La evidencia (sección 7) va a `docs/evidencia/M0-T0.1/`.
