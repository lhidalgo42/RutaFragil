## Hallazgos

### Mayores

**M1 — La capa `.tres` del loader no está probada, y el caso "base JSON inválido" afirma el default neutro.** `tests/core/data/game_data_loader_test.gd:105-114` escribe un JSON truncado y afirma `starting_money == 0`. El plan §6 exigía "`is_ok()` falso **y valores del `.tres`**". Ningún test escribe un `.tres` en un directorio inyectado (`grep ResourceSaver tests/` vacío); el único `.tres` que se carga es el real, cuyo JSON espejo tiene valores idénticos, así que `_load_tres_layer` podría aportar cero valores y toda la suite seguiría verde. Sin prueba quedan: la primera capa de D45, la degradación ante base inválida y `CACHE_MODE_IGNORE`. *Fix:* en el test, `TuningTable` con `starting_money = 321` guardado con `ResourceSaver.save(res, base_dir + "/tuning.tres")`; JSON base truncado → afirmar `is_ok()` falso **y** `321`; caso positivo `.tres`(321) + JSON(500) → 500 para fijar el orden de capas; y un caso de recarga tras reescribir el `.tres` (prueba `CACHE_MODE_IGNORE`).

**M2 — "Mod rechazado entero" no está demostrado.** `game_data_loader_test.gd:86-100`: el mod inválido tiene una sola clave; un rechazo por clave pasaría igual. No hay caso con dos secciones donde una falle (`staged`/`rejected` en `game_data_loader.gd:110-135`). *Fix:* mod `{"tuning": {"starting_money": "mucho", "rent_quota": 1}, "game_config": {"max_players": 2}}` sobre base `rent_quota 900`, `max_players 6` → afirmar 900, 6, `applied_files` solo con base y un `REJECTED` en avisos. En el codec, caso "modo laxo + error de tipo + clave hermana válida → `{}`".

**M3 — `DataLoadReport` sin test propio (R13) y ruta `String` del codec sin ejercitar.** `summary()` es la salida sobre la que descansan las evidencias 03–05 y no se afirma en ningún test. El fixture `codec_fixture.gd` declara `label_text` para probar `String` y ningún test lo usa. *Fix:* `tests/core/data/data_load_report_test.gd` (`is_ok`, formato de `add_error`/`add_warning`, `summary()` con cabecera y una línea por entrada); test de `String` válido e inválido en el codec.

**M4 — El estado "sin datos" es silencioso en el juego.** `game_data_loader.gd:38-40`: un documento sin `.tres` ni `.json` base es **aviso**, no error, así que `is_ok()` sigue verdadero; `game_config.gd:23-24` solo hace `push_error` si `!is_ok()`, y los avisos (incluidos los `REJECTED` de mods) **nunca se imprimen**; `print_game_data` sale con 0 sin datos. Escenario: `data/` faltante en un export → lobby para 0 jugadores sin una línea en consola. Contradice D44 ("el loader reporta en voz alta si faltan"). **Hueco compartido con el plan** (paso 5 dijo "`push_error` solo si `!is_ok()`"); decisión del revisor para la ronda 2: (a) documento sin ninguna capa aplicada = `add_error`, no aviso (es fallo de integridad, no problema de mod); (b) el autoload emite `push_warning` por cada aviso del reporte (los modders ven sus rechazos); `push_error` sigue reservado a `!is_ok()`. Actualizar D44/D45 y `esquema_v1.md`.
