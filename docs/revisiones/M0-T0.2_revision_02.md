**MR1 — El test de "sin datos" no existe.** El prompt A.1 pedía "directorios vacíos → `is_ok()` falso y un error por documento". La suite del loader tiene 12 tests y ninguno crea dos directorios vacíos; el único respaldo de M4 es la evidencia 09 a nivel de proceso. R13. *Fix:* `test_empty_dirs_fail_with_one_error_per_document`: dos `create_temp_dir`, `load_all()`, afirmar `is_ok()` falso, `errors.size() == 2`, `applied_files` vacío, y que los errores empiecen por `doc:game_config:` y `doc:tuning:`.

**MR2 — M1(c) está confundido.** `game_data_loader_test.gd:203-216` escribe `tuning.tres` y `tuning.json` truncado pero no escribe base de `game_config`; con M4 en el código, `game_config` sin capa ya produce un error, así que `is_ok()` es falso **aunque el JSON truncado se ignorara en silencio**. El test no afirma cuántos errores ni de qué fuente. *Fix:* escribir también `game_config` base; afirmar `errors.size() == 1` y que `errors[0]` empieza por `base:` + ruta del JSON truncado; conservar `321`.

**MR3 — La rama `push_warning` del autoload no está probada ni evidenciada.** `game_config_autoload_test.gd` no cambió; la evidencia 05 (mods inválidos, la única que provocaría avisos) es de la ronda 1 y no muestra ninguna línea `WARNING`; la 08 no lo declara. *Fix (cambio mínimo de firma, dentro del plan):* `reload(base_dir: String = "res://data", mods_dir: String = "user://mods") -> DataLoadReport`.
